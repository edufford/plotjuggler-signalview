Signal View Plugin - Feature Behavior Reference
================================================

Plugin type: PJ::ToolboxPlugin (FLOATING)
Accessed via: PlotJuggler > Tools > Signal View
Version: 0.9.0


TOOLBAR
-------
- "Add Signal" button: opens a dialog listing all numeric signals from all
  loaded data layers. Sorted alphabetically with a type-to-filter field.
  The same signal can be added multiple times for independent traces.
  Y range is auto-detected from data with 10% margin. New signals are added
  with 20% height bands at the top without changing existing signals.
- "Remove Signal" button: opens a dropdown listing currently added signals.
  Selecting one removes it. Remaining signals keep their current band positions.
- "Group" button: groups all currently selected signals so they overlap.
  Copies band position, band height, bar_x, divisions, Y min, and Y max from the topmost
  selected signal (lowest band_top) to all other selected signals. No-op if
  fewer than 2 signals are selected. After grouping, z_orders are reassigned
  so the highest-index signal in the group is immediately on top.
- "Auto Scale" button: sets the Y min/max of each selected signal (or all
  signals if none are selected) to automatically fit the Y range to the data
  within the current view time range (respecting time zoom). The margin added
  above and below the data extents is controlled by the adjacent "Margin:"
  spin box (0–100%, default 0%). The last data point before the view start is
  included for step-wise hold value accuracy. Signals with no data in view or
  constant data use a fallback margin of 1.0 regardless of the margin setting.
  Grouped signals (those sharing the same band position, height, and bar_x) are
  auto-scaled together: their data extents are combined across all signals in
  the group and a single common Y min/max is applied to all of them, so the
  group continues to display on a shared Y range after scaling.
- "Margin:" spin box: percentage of the Y range added as padding above and
  below signal extents when auto-scaling. Range 0–100%, default 0%.
- "Reset Zoom" button: resets the time axis to auto-fit all loaded data.
  Pushes the current zoom range onto the zoom history stack (if the view
  changes), so "Prev Zoom" can return to the pre-reset state.
- "Snap" dropdown: selects the position snapping grid size for bar and band
  dragging. Available values: Off, 0.002, 0.005, 0.01, 0.02, 0.05, 0.10, 0.20.
  Default: 0.01. Snapping is based on the top edge of the band (vertical)
  and bar_x (horizontal) when dragging bars or signal names/values. Edge
  resize drags snap the moving edge to the grid while leaving the fixed
  edge unchanged.
- "H. Zoom" toggle button: when checked, the scroll wheel performs time-axis
  zoom (centered on mouse position). When unchecked (default), the scroll
  wheel scrolls the view vertically. Button turns bright yellow when active.
  Canvas shows a custom cursor (arrow with magnifying glass).
  In H. Zoom mode, right-click drag continues to pan the time axis (same as
  default mode). Each zoom operation (rubber-band or scroll wheel) pushes the
  previous range onto the zoom history stack.
- "Prev Zoom" button: steps back through the zoom history one range at a time.
  Restores the view to the range before the most recent rubber-band zoom,
  scroll-wheel zoom, or "Reset Zoom". Disabled when the stack is empty;
  enabled automatically after any zoom operation that changes the view range.
  The stack persists for the entire application session and is not cleared
  when zoom mode is toggled off.
- "Time Shift" toggle button: when checked, left-click+drag on the canvas
  shifts the time offset of target data layers. The target layers are
  determined by the current signal selection (see DATA OVERLAY section).
  Mutually exclusive with "H. Zoom" — enabling one disables the other.
  Button turns bright yellow when active. Canvas shows a custom cursor
  (sine wave with horizontal double-arrow).
- "Layer:" combo box: selects the default layer to shift when no signals
  are selected in the Y-axis panel. Defaults to the highest layer index.
  Updated automatically when overlays are loaded or removed.
- "Overlay" button: opens a file picker to load a CSV overlay data file
  for comparison (see DATA OVERLAY section).
- "Dark/Light" toggle button: switches between dark mode (default) and light
  mode. In light mode the canvas background turns white, panel backgrounds turn
  light gray, grid lines darken, the cursor turns red, and signal colors are
  converted via an HSL lightness mirror (L → 1−L). Applying the mirror twice
  returns every color to its original value exactly (pure white ↔ pure black).
  New signals added while in light mode are automatically assigned mirrored
  palette colors. The button has no checked/highlight state.
- "Close" button: closes the Signal View and returns to PlotJuggler's default
  view. Emits the plugin's closed() signal which tells PlotJuggler to switch
  the stacked widget back to index 0. Can be reopened via Tools > Signal View.
- Version label: displays "Signal View vX.Y.Z" in the toolbar for identification.


LAYOUT: THREE-COLUMN Y-AXIS PANEL + PLOT CANVAS + SCROLLBAR
------------------------------------------------------------
The widget is split into a Y-axis panel (left), a plot canvas (middle),
and a vertical scrollbar (right). The panel and canvas are joined by a
QSplitter so the boundary is horizontally resizable. The scrollbar is
placed to the right of the splitter.

The scrollbar reflects the current vertical scroll position and allows
dragging to scroll. It is synchronized bidirectionally with the scroll
wheel: wheel scrolling updates the scrollbar, and dragging the scrollbar
updates the view. The scrollbar always provides at least 2 screens worth
of scrollable space (range extends to normalized position 2.0 minimum),
so there is usable space below even when no signals extend past the
initial viewport. If signals extend beyond that, the range grows to
accommodate them.

The Y-axis panel itself contains three columns joined by nested QSplitters:

  1. Signal Name Column (leftmost)
     - Displays the signal name in the signal's color (10pt bold sans-serif).
     - Text is elided with middle ellipsis if the column is too narrow.
     - Background is transparent (no per-band fill).
     - When multiple signals overlap vertically, names stack downward
       with no gap (15px row height). The highest signal claims the top
       slot. At the same vertical position, earlier-added signals (lower
       index) stay on top for stable, predictable stacking.

  2. Signal Value Column (middle)
     - Displays the cursor readout value for each signal in the signal's color.
     - Uses monospace bold 10pt font, 6 significant digits.
     - Shows "---" when no valid data exists at the cursor position.
     - Background is transparent (no per-band fill).
     - Values stack vertically in the same way as signal names when
       signals overlap, with matching row offsets.

  3. Y-Axis Bar Column (rightmost)
     - Displays a vertical axis bar for each signal with:
       - A single colored vertical stripe serving as the axis line.
       - Horizontal grab handles at the top and bottom edges.
       - Tick marks and numeric value labels along the axis.
       - Number of ticks: uses the signal's divisions setting (default 8).
         Setting divisions to 0 auto-scales based on band height
         (min 2, max 32, ~1 per 32px).
     - Background is transparent (no per-band fill).
     - Each bar has a horizontal position (bar_x) within the column.
       Bars default to the right edge (bar_x=1.0) and can be dragged
       horizontally to any position, allowing bars to be placed side by side.
     - Z-order: each signal has a z_order value (saved with the layout).
       Bars are painted unselected-first then selected-on-top, and within each
       tier in ascending z_order so the most recently interacted bar in a stack
       is always visible. When signals are first added or stacked together,
       z_orders are immediately assigned so the highest-index signal (painted
       on top) has the highest z_order — no click is needed to establish the
       initial ordering. Clicking a signal in any column (name, value, or bar
       body) bumps its z_order above all others; the topmost bar persists even
       after the selection is cleared. Hit-testing (click or edge-grab on a
       stacked group) always targets the bar with the highest z_order, matching
       the visual stacking. After each update, all z_order values are
       renormalized to [0, n-1] so they never grow unboundedly.

All three columns and the panel/canvas boundary are independently resizable
via QSplitter drag handles.


SIGNAL BANDS
------------
Each signal occupies a vertical "band" on the canvas and Y-axis panel.
Bands are defined by:
  - band_center: normalized vertical position where 0=top of initial view,
    1=bottom. Values beyond 1.0 are accessible by scrolling down.
  - band_height: fraction of the plot area height.
  - bar_x: horizontal position of the Y-axis bar [0=left, 1=right], default 1.0.
  - divisions: number of Y-axis tick divisions, default 8. 0 = auto-scale.

When a signal is added, it gets a 20% height band at the top.
When a signal is removed, remaining signals keep their current band positions.
Positions are snapped to the current snap grid. Dragging and top-edge resizing
are clamped so the top edge of a band cannot go above position 0 (absolute top).

Band positions are shared between the canvas and all Y-axis panel columns
using the AxisLayout::bandTopY / bandBottomY helpers, which account for
the canvas margin constants (top=10px, bottom=40px, left=10px, right=20px)
and the current vertical scroll offset.

VERTICAL SCROLLING
------------------
The entire view (canvas and all Y-axis columns) can be scrolled vertically
using the mouse scroll wheel. This reveals plotting space below the initial
visible area, allowing signals with band_center > 1.0 to be reached.

  - Scroll wheel: scrolls down (positive offset) or up. The scroll offset
    is clamped to >= 0 (cannot scroll above the top).
  - Each scroll notch moves the view by 5% of the plot height.
  - When the "H. Zoom" toolbar button is toggled on, the scroll wheel
    performs time-axis zoom instead (see TOOLBAR section).
  - Signals can be dragged below the initial [0,1] visible area and
    scrolled to. There is no upper clamp on band positions.


PLOT CANVAS
-----------
Rendering:
  - Dark mode background (30,30,30); light mode background white (255,255,255).
  - Plot area bordered by a gray rectangle (darker in light mode).
  - Dotted grid lines: per-signal horizontal lines aligned to each signal's
    Y-axis tick divisions (same count as the Y-axis bar column ticks). Color:
    (80,80,80) in dark mode, (170,170,170) in light mode. ~8 vertical lines
    with "nice" step spacing use the same color.
  - Signal traces rendered as step-wise (staircase) antialiased QPainterPaths,
    clipped to plot area. Values are held constant until the next data point,
    then step vertically to the new value.
  - Binary search is used to skip directly to the first visible data point
    instead of scanning from the beginning of the series.
  - Per-pixel-column downsampling: when the number of visible data points
    exceeds twice the pixel width of the plot area, points are aggregated
    per pixel column. For each column, the first, min, max, and last Y
    values are emitted, preserving the full vertical extent of the signal
    at that pixel. This is visually identical to full-resolution rendering
    but reduces the QPainterPath element count from potentially millions
    to at most ~4 per pixel column.
  - Traces outside the view range are culled, with boundary points preserved
    to avoid clipping artifacts.
  - Optional data point markers drawn at each sample within the view range.
    Markers are automatically suppressed when downsampling is active (points
    are sub-pixel). Marker styles: None (default), Filled Circle, Open Circle,
    Filled Square, Open Square, Filled Triangle, Open Triangle. Marker size scales with
    line width. Filled markers use solid fill; open markers use outline only.

Time axis:
  - Drawn below the plot area with tick marks and labels.
  - Nice tick spacing (1, 2, 5 multiples of powers of 10).
  - Decimal precision adapts to tick step size.
  - "Time (s)" label centered at the bottom.
  - Editable time range fields at the bottom corners of the plot area:
    - Start time field at the bottom-left corner shows the view's start time.
    - End time field at the bottom-right corner shows the view's end time.
    - Fields update live during pan, zoom, and auto-fit.
    - Editing a value and pressing Enter (or losing focus) sets the view
      range and disables auto-fit. Invalid values are reverted.

Cursor:
  - Dark mode: vertical dashed yellow line with a small yellow triangle handle.
  - Light mode: vertical dashed red line with a small red triangle handle.
  - In default mode, shows SizeHorCursor when hovering within 5px of the cursor line.
  - In H. Zoom mode, shows a custom magnifying glass cursor.
  - In Time Shift mode, shows a custom sine wave + arrow cursor.

Auto-fit:
  - When enabled (default), the time range auto-fits to the data extents.
  - Auto-fit is disabled when the user pans or zooms manually.
  - Re-enabled by clicking "Reset Zoom".


SIGNAL SELECTION
----------------
Signals can be selected in any Y-axis panel column:
  - Click or drag on a signal (name, value, or bar body): selects that
    signal on press. If the signal is already selected, the selection is
    preserved (enabling double-click and multi-selection drag).
  - Ctrl+click: toggles the signal in/out of the selection.
  - Click on empty area: clears the selection.
  - Click + drag on empty area: rubber band selection. In the name and
    value columns, a signal is selected when the rubber band overlaps its
    15px text row (at its stacked position). In the bar column, a signal
    is selected when the rubber band overlaps both the bar's vertical
    extent and its horizontal axis position. Ctrl+drag adds to the
    existing selection.
  - Selected signals get a neutral gray highlight (160,160,160 at 31% opacity)
    in the name and value columns, visible on both dark and light backgrounds.
  - Clicking a signal in any column (name, value, or bar body) bumps its
    z_order to the top of its stack so its bar remains visible. The z_order
    persists after the selection is cleared and is saved with the layout.

Multi-signal operations (when multiple signals are selected):
  - Dragging a selected signal moves all selected signals together,
    preserving their relative vertical positions.
  - Dragging a selected Y-axis bar also moves all selected bars
    horizontally together, preserving their relative bar_x positions.
  - Resizing a selected signal's band edge applies the same height
    change to all selected signals (same edge direction).
  - Pressing Delete removes all selected signals and clears the
    selection.
  - Ctrl+A selects all signals.


MOUSE INTERACTION: SIGNAL NAME COLUMN
--------------------------------------
- Click area: only the 15px text row at the top of each band (not the
  full band height).
- Left click on signal: selects on press, drag repositions the signal's
  band vertically (see SIGNAL SELECTION above).
  - Shows OpenHandCursor on hover, ClosedHandCursor while dragging.
  - Drag index is propagated to the value column so stacking stays
    consistent across all columns during the drag.
- Left click + drag on empty area: rubber band selection.
- Right click on signal: opens a context menu (see SIGNAL CONTEXT MENU).
- Mouse wheel: scrolls the view vertically (see VERTICAL SCROLLING).
- Double click on signal: opens the Y-range table dialog for the clicked
  signal (plus any selected signals).
- Double click on empty area: opens the Add Signal dialog. The new signal's
  band is placed at the vertical position of the double-click.


MOUSE INTERACTION: SIGNAL VALUE COLUMN
---------------------------------------
- Click area: only the 15px text row at the top of each band (not the
  full band height).
- Left click on signal: selects on press, drag repositions the signal's
  band vertically (same behavior as the name column).
  - Shows OpenHandCursor on hover, ClosedHandCursor while dragging.
  - Drag index is propagated to the name column.
- Left click + drag on empty area: rubber band selection.
- Right click on signal: opens a context menu (see SIGNAL CONTEXT MENU).
- Mouse wheel: scrolls the view vertically (see VERTICAL SCROLLING).
- Double click on signal: opens the Y-range table dialog (same as name column).
- Double click on empty area: opens the Add Signal dialog. The new signal's
  band is placed at the vertical position of the double-click.


MOUSE INTERACTION: Y-AXIS BAR COLUMN
--------------------------------------
- Click area: full vertical height of the band, plus 8px grab zones
  beyond the top and bottom edges.

- Left click on BODY: selects the signal (see SIGNAL SELECTION above).

- Left click + drag on BODY: repositions the signal's band vertically
  and the bar horizontally (2D movement).
  - Shows SizeAllCursor on hover and while dragging.
  - Horizontal movement is clamped to [0, 1] normalized bar_x range.
  - Drag index is propagated to name and value columns so stacking
    stays consistent across all columns during the drag.

- Left click + drag on empty area: rubber band selection.

- Left click + drag on TOP EDGE: resizes the band by moving the top edge.
  - Y min/max values remain the same; only band_center and band_height change.
  - Minimum band height enforced at 2% of plot area.
  - Shows SizeVerCursor.

- Left click + drag on BOTTOM EDGE: resizes the band by moving the bottom edge.
  - Same behavior as top edge but in the opposite direction.
  - Shows SizeVerCursor.

- Right click on a band: opens a context menu (see SIGNAL CONTEXT MENU).

- Double click on a band: opens the Y-range table dialog.

- Double click on empty area: opens the Add Signal dialog. The new signal's
  band is placed at the vertical position of the double-click.

- Mouse wheel: scrolls the view vertically (see VERTICAL SCROLLING).


Y-RANGE TABLE DIALOG
--------------------
Opened by double-clicking any signal in the name, value, or bar column.
Shows a table with one row per signal (the clicked signal plus any that
are currently selected).

Columns:
  - Signal: read-only name in the signal's color.
  - Color: clickable color swatch button. Opens a QColorDialog to pick a new
    color. When multiple rows are selected, changing one row's color applies
    to all selected rows. The signal name text color updates to match.
  - Line Style: dropdown combo box with options: Solid, Dash, Dot, Dash-Dot,
    Dash-Dot-Dot. Default: Solid. Propagates to all selected rows.
  - Marker: dropdown combo box with options: None, Filled Circle, Open Circle,
    Filled Square, Open Square, Filled Triangle, Open Triangle. Default: None.
    Propagates to all selected rows.
  - Line Width: editable numeric field (validated 0.1–10.0, 1 decimal place).
    Default: 1.5. Propagates to all selected rows.
  - Y Min: editable numeric text field (validated as double, 6 significant digits).
  - Y Max: editable numeric text field (validated as double, 6 significant digits).
  - Divisions: editable integer field (validated 0–32, default 8).
    0 means auto-scale based on band height. Values > 0 set a fixed number
    of Y-axis tick divisions.

All rows are selected by default. When a value is changed in any editable
column, the new value is automatically applied to the same column of all
other selected rows in the table, enabling batch editing. Rows can be
deselected in the table for individual editing.

Clicking into a text field preserves the row selection if that row is
already selected. If the row is not selected, the selection is cleared
and only that row becomes selected.

OK applies changes; Cancel discards. Changes are only applied if Y Max > Y Min.


SIGNAL CONTEXT MENU
-------------------
Right-clicking any signal in the name, value, or Y-axis bar column opens a
context menu. Which signals are affected depends on the current selection:
  - If the right-clicked signal is part of the current selection, all
    actions apply to all selected signals.
  - If the right-clicked signal is not selected, all actions apply
    only to that one signal.

Actions:
  - "Auto Scale": sets Y min/max to fit the signal's data within the
    current view time range, using the current Margin % setting. Identical
    to clicking the toolbar "Auto Scale" button, but scoped to the target
    signals above (never falls back to all signals). Grouped signals among
    the targets share a combined Y range (see toolbar Auto Scale).
  - "Change Style...": opens the Y-range table dialog for the target signal(s).
  - "Group": overlaps all target signals onto the same band position, height,
    Y range, and bar_x, copying from the topmost signal. Identical to the
    toolbar "Group" button. Only enabled when 2 or more signals are selected
    and the right-clicked signal is part of the selection.
  - "Remove": removes the target signal(s). Remaining signals keep their
    current band positions.


MOUSE INTERACTION: PLOT CANVAS
-------------------------------
- Left click on empty area (default mode): no action.

- Left click within 5px of the cursor line (default mode): begins cursor
  dragging from the cursor's current position. The cursor does not jump
  on press; movement begins only when the mouse is dragged.

- Left click + drag on cursor line (default mode): drags the cursor along
  the time axis. Movement is relative to the click position. Continuously
  updates cursor readout values in the signal value column.

- Double left click anywhere (default mode): jumps the cursor to the
  clicked time position. Cursor time is clamped to the current view range.
  The OS cursor icon updates immediately to SizeHorCursor.

- Left click + drag (H. Zoom mode): shows a rubber-band vertical band
  (semi-transparent yellow overlay with edge lines) between the click
  point and the current cursor position. On button release, zooms the
  time axis to the selected range. Disables auto-fit. A click without
  meaningful drag (< 1ns range) is ignored.

- Left click + drag (Time Shift mode): shifts the time offset of the
  target data layers. Target layers are determined by the current signal
  selection: if signals from layers #1 and #3 are selected, both layers
  shift simultaneously. If no signals are selected, the layer from the
  "Layer:" combo box is shifted.

- Right click + drag: pans the time axis. Disables auto-fit. Applies in all
  modes (default, H. Zoom, and Time Shift). Pushes the pre-pan range onto the
  zoom history stack on press, so "Prev Zoom" can return to it.
  - Shows ClosedHandCursor while panning.

- Mouse wheel (default): scrolls the view vertically (see VERTICAL SCROLLING).

- Mouse wheel (H. Zoom mode): zooms the time axis in/out (0.8x / 1.25x
  factor), centered on the mouse position. Disables auto-fit. Pushes the
  previous range onto the zoom history stack.


KEYBOARD INTERACTION: PLOT CANVAS
----------------------------------
The canvas accepts keyboard focus (click on it to focus).

- Left arrow: moves the cursor one pixel to the left. The step size equals
  one pixel's worth of time at the current zoom level
  (view_range / plot_width_in_pixels), so it scales automatically with zoom.

- Right arrow: moves the cursor one pixel to the right, same step size.

Both keys clamp the cursor to the current view range and emit cursorMoved,
updating the signal value column readout.


CURSOR READOUT
--------------
When the cursor moves, the plugin performs a step-wise (sample-and-hold)
lookup for each signal: it finds the last data point at or before the
cursor time and displays that value. This matches the step-wise line
rendering where the value holds constant until the next sample. If the
signal has no data before the cursor time, "---" is shown.


COLOR ASSIGNMENT
----------------
Signals are assigned colors in order from a predefined dark-mode palette:
  1. Cyan-blue    (#00B4FF)
  2. Orange-red   (#FF6432)
  3. Green        (#32DC64)
  4. Yellow       (#FFDC32)
  5. Purple       (#C850FF)
  6. Pink         (#FF64B4)
  7. Teal         (#64FFDC)
  8. Amber        (#FFA032)
Colors cycle if more than 8 signals are added.

In light mode, signal colors are converted via an HSL lightness mirror
(L → 1−L). This transform is its own inverse: applying it twice returns
the original color exactly. Palette colors assigned while in light mode are
automatically mirrored at assignment time.

The color stored in sig.color always reflects the active theme. Colors
chosen via the Y-range table dialog are used as-is (no automatic mirroring
at the time of selection; they will be mirrored the next time the theme is
toggled, like all other signal colors).


DATA OVERLAY
------------
The plugin supports overlaying data from multiple CSV files for comparison.
Each data source is assigned a layer number. Layers are managed by the
OverlayManager class.

Signal naming convention:
  - #1/velocity    — base PlotJuggler data (layer 1)
  - #2/velocity    — first overlay file (layer 2)
  - #3/velocity    — second overlay file (layer 3)
  - velocity       — unprefixed (backward compatible, treated as layer 1)

When no overlays are loaded, signal names remain unprefixed. When the first
overlay is loaded, existing signals are prefixed with #1/. When all overlays
are removed, prefixes are stripped.

Loading an overlay:
  1. Click "Overlay" button or right-click in the Data Sets Panel → "Load Overlay..."
  2. Select a CSV file (supports comma, tab, or semicolon delimiters).
     First column is treated as time. Each subsequent column becomes a signal.
  3. Auto-match: for each currently displayed signal's raw name, matching
     signals in the overlay file are automatically added with the same band
     position, Y range, and dimensions, but with a different color and
     dashed line style.
  4. Additional signals from any loaded data set can be added via the
     "Add Signal" dialog, which lists all signals from all layers.

Each data file may have different time steps and/or variable time steps.
Each layer stores its own independent PlotData time series.

Time shifting:
  - Enable "Time Shift" mode via the toolbar toggle button.
  - Left-click + drag on the canvas shifts the time offset of target layers.
  - Target layers are determined by the Y-axis panel selection:
    - If signals are selected, all distinct layers in the selection shift
      simultaneously by the same time delta.
    - If no signals are selected, the layer indicated by the "Layer:" combo
      box is shifted (defaults to the highest layer index).
  - Time offsets are applied additively: rendering uses (time + offset),
    cursor lookups use (cursor_time - offset).
  - All layers are independently shiftable, including the base layer #1.

Removing an overlay:
  - Right-click the layer in the Data Sets Panel → "Remove Overlay".
  - All signals from that layer are removed.
  - If no overlays remain, signal names are un-prefixed.

Clearing all overlays at once:
  - Right-click any layer in the Data Sets Panel → "Clear All Overlays".
  - All overlay layers (2+) and their signals are removed in one step.
  - Signal names are un-prefixed after the operation.


DATA SETS PANEL
---------------
A compact footer widget displayed below the canvas at all times (even with
a single data layer). Lists all loaded data layers.

Each row shows:
  - Layer number (#1, #2, ...)
  - Display name: "PJ Data" for the PlotJuggler base layer, or the CSV
    filename (basename) for overlay layers.
  - Time offset value (e.g., "offset: +0.053s"), updated live during drag.

Interactions:
  - Double-click the display name to rename it (e.g., rename "PJ Data" to
    a more descriptive label for screenshots).
  - Right-click opens a context menu:
    - "Style All Signals...": opens a dialog to set Color, Line Style, and
      Line Width for all signals from that layer.
    - "Rename...": opens an input dialog to rename the layer.
    - "Remove Overlay": removes the overlay layer (only for layers 2+).
    - "Clear All Overlays": removes all overlay layers at once (only shown
      when at least one overlay is loaded).
    - "Load Overlay...": opens the file picker to add another overlay.

When PlotJuggler provides no data, the first overlay file loaded becomes
layer #1. Subsequent overlays become #2, #3, etc.


LAYOUT SAVE / RESTORE
----------------------
The plugin implements xmlSaveState / xmlLoadState for PlotJuggler layout files.

Saved state includes:
  - Widget visibility (visible="0" or "1").
  - For each signal: name (with layer prefix if overlays exist), color, y_min,
    y_max, band_center, band_height, bar_x, divisions, line_style, line_width,
    marker_style, z_order.
  - Cursor time position.
  - View time range (t_min, t_max).
  - Settings: snap amount, theme (0=Dark, 1=Light).
  - Column widths: main splitter (panel|canvas), panel splitter (label|bar),
    label splitter (name|value).
  - For each overlay layer: layer index, display name, file path, time offset.
    The base layer's time offset and display name are also saved.

On layout load:
  - Signals are restored without checking data existence (data is loaded
    after plugin state by PlotJuggler's load order).
  - Theme is restored via applyTheme(): sets the rendering theme and button
    state without re-applying the color mirror (signal colors in the XML are
    already stored in the correct theme's color space).
  - Overlay CSV files are reloaded from their saved file paths, and time
    offsets and display names are restored. If an overlay file is missing,
    it is silently skipped.
  - View range and cursor position are restored.
  - If the widget was visible, the plugin switches PlotJuggler's internal
    QStackedWidget to show itself and calls onShowWidget().

Usage:
  Linux:   ./run.sh -l dev_layout.xml
  Windows: run.bat -l dev_layout.xml


BUILD & RUN
-----------
Linux:
  Build:   ./build.sh
  Test:    ./test.sh
  Run:     ./run.sh [-d data.csv] [-l layout.xml]
  Install: cmake --install build

Windows:
  Build:   build.bat [vs2022]
  Test:    test.bat [vs2022]
  Run:     run.bat [-d data.csv] [-l layout.xml]
  Install: cmake --install build --config Release

  Both build.bat and test.bat default to Visual Studio 18 2026.
  Pass "vs2022" as the first argument to use Visual Studio 17 2022 instead:
    build.bat vs2022
    test.bat vs2022
